**How the layers connect:**
- **Dependency direction:** pages use components and hooks, those use the api layer, and the api layer uses config. Pages never call `fetch` directly.
- **Error handling:** [httpClient.js](frontend/src/api/httpClient.js) reads your backend's `{ error: { message, details } }` error format and turns it into an `ApiError`.
- **Response unwrapping:** [item.api.js](frontend/src/api/item.api.js) strips the backend's `{ data }` wrapper, so pages get the items directly.
- **No CORS setup needed:** the dev server forwards `/api` to `http://localhost:5000`. You can change the target with `VITE_API_PROXY_TARGET` in `.env`.

**Versions:** npm installed the newest releases: React 19.3, React Router 8.4, Vite 8 and ESLint 10. One lint config line ([eslint.config.js](frontend/eslint.config.js)) had to change to fit the newer React hooks lint plugin.

To run it: `cd frontend && npm run dev`, with the backend also running. The scripts `build`, `preview` and `lint` are available too.

**How each requirement is covered:**

| Requirement | In the app |
|---|---|
| Add, update, remove products | Products page: Add / Edit / Delete, plus Edit and Delete on each product's page |
| Product details (name, price, code) | Product page: all fields, stock value and that product's history |
| Sort and filter | Click column headers to sort. Filter by search, category, in/out of stock, price range and quantity range. Filters are kept in the URL, so a filtered view can be bookmarked or shared |
| Increase / decrease stock | "Adjust stock" in a pop-up on the list, or a form on the product page. Shows current → new quantity and takes an optional reason |
| Stock never below zero | The form blocks the decrease and explains why. The backend also rejects it (status 422) |
| Total stock per category | Dashboard table with units, value and each category's share; also on the Categories page |
| History of all changes | History page with filters for type, date range and product. It includes history of deleted products |

Categories can also be managed on their own page (add, rename, delete). Delete is disabled for a category that still has products, which matches the backend rule.

**A few design choices worth knowing:**
- **Quantity on edit:** the edit form has no quantity field, because the backend only accepts quantity changes through the stock-adjust endpoints. That keeps every change in the history. The form shows a note explaining this.
- **Validation:** forms check the same limits as the backend before sending, such as at most 2 decimal places on price. If the backend still rejects something (e.g. a duplicate product code), its message appears next to the right field.
- **Feedback and theme:** success and error messages appear as pop-up notifications, and the app follows the system light/dark theme.
- **Dependencies:** no new packages were added. It's still only React, React Router and Vite.
